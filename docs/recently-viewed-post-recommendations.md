# 최근 본 상품과 비슷한 상품 모바일 연동

홈의 추천 영역은 앱이 최근 본 상품 ID를 보내면, 서버가 현재 상품 정보로 추천 순서를 정해 판매 중인 상품을 반환한다. 앱이 관리하는 열람 기록은 기기와 계정에 귀속되며, 서버는 전달된 ID를 요청 처리에 사용한다. [백엔드 이슈 #103](https://github.com/kitschcatch-App/kitschcatch-backend/issues/103).

## 요청

```http
POST /api/posts/recommendations/recently-viewed
Authorization: Bearer {accessToken}
Content-Type: application/json
```

```json
{
  "recentPostIds": [123, 98, 75],
  "limit": 10
}
```

| 필드 | 계약 |
| --- | --- |
| `recentPostIds` | 필수 배열. 가장 최근에 본 상품부터 최대 20개. 각 값은 양의 64비트 정수. 빈 배열 허용. |
| `limit` | 선택 정수. 1~20 범위. 생략하면 10개. |

중복 ID는 처음 나온 위치만 사용한다. 요청 배열의 20개 제한은 중복을 제거하기 전에 적용한다. 가격, 카테고리, 판매 상태는 서버가 현재 상품 정보로 확인한다.

## 추천 기준

카테고리마다 가장 최근에 본 유효한 상품을 기준으로 삼는다. 예를 들어 최근 열람 순서가 굿즈 30,000원 → 게임 50,000원 → 굿즈 15,000원이면 굿즈는 30,000원, 게임은 50,000원을 기준으로 계산한다.

1. 최근에 본 카테고리를 우선한다.
2. 같은 카테고리에서는 기준 상품과의 `price` 차이가 작은 순으로 정렬한다.
3. 가격 차이가 같으면 생성 시각 내림차순, 생성 시각도 같으면 상품 ID 내림차순으로 정렬한다.

기준으로 삼을 수 있는 상품은 판매 중·예약 중·판매 완료 상품이다. 존재하지 않거나 삭제된 상품, 본인 상품, 탈퇴 판매자의 상품, 어느 방향이든 차단 관계가 있는 판매자의 상품은 기준에서 건너뛴다.

추천 결과는 기준 카테고리의 `ON_SALE` 상품 중 동일한 제외 조건을 통과한 상품으로 구성한다. 앱이 전달한 최근 본 ID는 모두 결과에서 제외한다. 조건을 만족하는 상품이 `limit`보다 적으면 찾은 수만 반환한다.

## 성공 응답

HTTP 200. `posts`의 개별 항목은 [기존 상품 목록](issue-47-post-search.md)과 같은 `PostResponse`다.

```json
{
  "success": true,
  "data": {
    "limit": 10,
    "posts": [
      {
        "id": 456,
        "sellerId": 21,
        "sellerNickname": "굿즈모으는사람",
        "title": "캐릭터 아크릴 키링",
        "description": "미개봉 상품입니다.",
        "price": 28000,
        "productCategory": "굿즈",
        "productCondition": "NEW",
        "productStatus": "ON_SALE",
        "images": [
          {
            "imageKey": "posts/21/example.png",
            "imageUrl": "https://example.com/temporary-image-url",
            "sortOrder": 0
          }
        ],
        "createdAt": "2026-11-09T10:00:00",
        "updatedAt": "2026-11-09T10:00:00",
        "favoriteCount": 7,
        "chatRoomCount": 2,
        "shippingAmount": 3000
      }
    ]
  }
}
```

`limit`은 요청에 적용한 최대 개수다. 실제 개수는 `posts.length`다. 최근 본 기록, 유효한 기준 상품 또는 후보가 없으면 HTTP 200으로 `{"success":true,"data":{"limit":10,"posts":[]}}`를 반환한다. 일부 ID만 유효하면 해당 기준으로 계속 추천한다.

`productCategory`는 기존 한글 라벨이다. `shippingAmount`는 기존 데이터에 따라 null일 수 있다. `favoriteCount`는 전체 관심 등록 수다. 사용자의 개인 관심 상태는 기존 관심 상품 기능의 상태를 사용한다.

## 오류 응답

| HTTP | 코드 | 조건 |
| --- | --- | --- |
| 400 | `COMMON_001` | 배열 누락·null, 20개 초과, 배열 안의 null 또는 0 이하 ID, 개수 범위 오류. |
| 400 | `COMMON_002` | JSON 문법 오류, 배열 대신 다른 타입, 정수 필드의 문자열·소수·표현 범위 초과, `limit`의 명시적 null. |
| 401 | `AUTH_004` | 유효한 액세스 토큰 또는 활성 계정이 없음. |

오류는 기존 `{"success":false,"error":{"code":"COMMON_001","message":"입력값이 올바르지 않습니다."}}` 형식을 사용한다. 값 검증 오류에는 필드별 오류가 추가될 수 있다.

## 홈 연결

1. 상품 상세 조회가 성공하면 계정별 로컬 목록 맨 앞에 ID를 기록한다. 이미 있으면 맨 앞으로 이동하고 가장 최근 20개만 유지한다. 로그아웃·탈퇴 시 해당 계정의 로컬 기록을 정리한다.
2. 홈 진입과 갱신에서 최신순 ID를 보낸다. 계정이 바뀌거나 새 요청이 시작되면 요청 식별자를 확인해 이전 응답을 폐기한다.
3. 응답 순서대로 표시하고 빈 배열이면 추천 영역을 숨긴다. 일시적 오류는 추천 영역에서 재시도를 제공하고 401은 기존 인증 흐름으로 처리한다.
4. 카드에서 `id`로 기존 상세를 열고 최신 가격과 판매 상태를 확인한다. 카드 대표 이미지는 `images`의 첫 항목을 사용한다. 이미지 URL이 만료되면 기존 상품 API로 갱신한다.

개발 서버 반영 후 최근 기록 없음, 같은 상품 재열람, 계정 전환, 삭제된 최근 상품이 섞인 요청을 확인한다. 홈에서 새 추천 요청을 연달아 보냈을 때 최신 응답이 표시되는지도 확인한다.
