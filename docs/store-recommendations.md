# 매장 지도 ‘다른 가게 추천’ 모바일 연동

[백엔드 이슈 #101](https://github.com/kitschcatch-App/kitschcatch-backend/issues/101). 사용자가 지도에서 매장을 선택하면 그 매장 주변에서 함께 방문할 수 있는 다른 매장을 보여 준다. 현재 사용자 위치를 기준으로 탐색하는 경우에는 [기존 주변 매장 API](store-map.md#주변-매장)를 사용한다.

## 요청

```http
GET /api/stores/123/recommendations?radiusKm=5&limit=5
Authorization: Bearer {accessToken}
```

| 항목 | 규칙 |
| --- | --- |
| `storeId` | 경로에 넣는 기준 매장 ID. 양의 정수. |
| `radiusKm` | 선택. 1·3·5km 중 하나이며 기본값은 5km. |
| `limit` | 선택. 최대 반환 개수로 1~10의 정수이며 기본값은 5개. |

기본값이면 `GET /api/stores/123/recommendations`로 호출한다. 위도·경도나 위치 권한은 필요 없다. 거리 계산에는 서버가 보관한 기준 매장의 좌표를 사용한다.

## 성공 응답

HTTP 200. 아래는 반경 안의 후보가 2개인 예시다.

```json
{
  "success": true,
  "data": {
    "sourceStoreId": 123,
    "radiusKm": 5,
    "limit": 5,
    "stores": [
      {
        "id": 456,
        "name": "예시 굿즈 매장",
        "address": "서울특별시 마포구 예시로 10",
        "latitude": 37.553,
        "longitude": 126.925,
        "distanceMeters": 334,
        "favorited": true
      },
      {
        "id": 789,
        "name": "예시 캐릭터 숍",
        "address": "서울특별시 마포구 예시로 20",
        "latitude": 37.556,
        "longitude": 126.925,
        "distanceMeters": 667,
        "favorited": false
      }
    ]
  }
}
```

| 필드 | 의미 |
| --- | --- |
| `sourceStoreId` | 추천 기준 매장 ID. |
| `radiusKm`, `limit` | 서버가 적용한 반경과 최대 개수. 실제 개수는 `stores.length`. |
| `stores[].id`, `name`, `address` | 추천 매장 식별자·이름·주소. |
| `stores[].latitude`, `longitude` | WGS84 십진수 좌표. 네이버 지도 SDK의 위도·경도 순서. |
| `stores[].distanceMeters` | 선택한 매장부터 추천 매장까지의 구면 직선거리를 미터 단위로 반올림한 정수. |
| `stores[].favorited` | 현재 로그인 사용자가 등록한 관심 여부. |

`stores` 항목은 기존 주변 매장 응답과 같은 필드다. 서버는 반올림 전 거리, 매장 ID 순서로 정렬한다. 기준 매장의 ID를 제외하며, 좌표가 같은 다른 매장은 거리 0m로 포함될 수 있다. 반경에 들어오면 시·도가 달라도 포함한다.

반경 안에서 찾은 후보만 최대 `limit`개까지 반환한다. 후보가 없으면 HTTP 200에 `"stores": []`를 반환한다. 추천 응답에는 페이지나 `hasNext`가 없다. 대표 사진·평점·영업시간은 매장을 선택한 뒤 기존 상세 응답으로 표시한다.

## 오류 응답

| HTTP | 코드 | 조건 |
| --- | --- | --- |
| 400 | `COMMON_002` | 매장 ID 형식 오류 또는 0 이하. |
| 400 | `STORE_002` | 반경 형식 오류 또는 허용하지 않는 반경. |
| 400 | `COMMON_001` | 개수 형식 오류 또는 1~10 범위를 벗어남. |
| 401 | `AUTH_004` | 유효한 액세스 토큰이 없음. |
| 404 | `STORE_001` | 기준 매장이 없음. |

```json
{
  "success": false,
  "error": {
    "code": "STORE_001",
    "message": "매장을 찾을 수 없습니다."
  }
}
```

## 화면 연결

1. 매장을 선택하면 선택한 ID로 추천을 조회한다. 선택이 바뀌면 이전 목록을 비우고 새 요청을 보낸다. 이전 요청을 취소하거나 요청 시점의 선택을 확인해 늦게 도착한 응답을 무시한다.
2. 응답 순서대로 카드를 표시한다. 거리 라벨은 ‘이 매장에서 334m’처럼 기준을 드러낸다. 현재 사용자와의 거리나 도보 거리로 해석하지 않는다.
3. 카드를 선택하면 응답의 `id`와 좌표로 지도 선택 상태를 바꾸고 `GET /api/stores/{id}`로 상세를 연다. 관심 상태 변경은 [기존 관심 매장 API](store-favorites.md)를 사용하고 성공 응답으로 카드 상태를 갱신한다.
4. 빈 배열은 성공이다. 추천 영역을 숨기거나 주변 추천 매장이 없다는 안내를 표시한다. 일시적 실패는 기존 상세를 유지하면서 추천 영역에 재시도를 제공한다. 401은 기존 인증 흐름에 맡기고, 기준 매장 404는 매장 목록을 갱신하고 선택을 해제한다.

개발 서버에 반영된 후 위치 권한을 끈 상태로 매장을 선택해 추천을 확인한다. 등록 매장이 밀집한 곳과 후보가 없는 곳을 각각 확인하고, 매장을 빠르게 바꿨을 때 현재 선택의 추천만 남는지 확인한다. 관심 매장을 등록한 계정과 등록하지 않은 계정에서 같은 추천의 `favorited`가 각 계정 상태와 일치하는지도 확인한다.
