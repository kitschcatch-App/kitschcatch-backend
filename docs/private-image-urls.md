# 비공개 S3 상품·프로필 이미지 조회

상품과 프로필의 `imageUrl`·`profileImageUrl`은 S3 GET 서명 URL이다. 버킷의 공개 접근을 허용할 필요가 없다. 업로드 URL의 PUT 서명과 조회 URL의 GET 서명은 별도로 발급한다.

## 적용 범위

- 상품 업로드 URL 발급 응답과 상품 생성·검색·상세·수정·판매자별 목록·관심 상품 응답의 이미지 URL.
- 프로필 업로드 URL 발급 응답과 프로필 등록·내 정보·공개 프로필·수정·팔로우 목록 응답의 이미지 URL.
- 상품 이미지 저장소를 사용하는 채팅방 상세 대표 이미지와 주문 상세 대표 이미지.

DB에는 기존 객체 키만 저장한다. 응답을 만들 때마다 저장된 키로 서명하므로 기존 이미지도 다시 업로드하거나 DB를 변경할 필요가 없다. 이미지가 없는 응답은 기존 null 계약을 유지한다. 채팅 메시지 첨부 이미지의 저장·조회 방식은 이번 변경에 포함하지 않는다.

## 서버 설정

| 환경 변수 | 용도 |
| --- | --- |
| `APP_S3_BUCKET` | 이미지가 저장된 비공개 버킷. 필수. |
| `APP_S3_REGION` | 버킷 리전. 기본 `ap-northeast-2`. |
| `APP_S3_DOWNLOAD_URL_TTL` | 상품·프로필 GET 서명 URL 유효기간. 기본 `15m`. 1초 이상 7일 이하의 정수 초. |
| `APP_S3_PUBLIC_BASE_URL` | 상품·프로필과 해당 대표 이미지에는 사용하지 않는다. 기존 채팅 첨부 이미지에는 여전히 적용된다. |

AWS SDK 기본 자격 증명 체인을 사용한다. 서버 IAM 역할에는 대상 객체의 `s3:GetObject` 권한이 필요하며, 기존 업로드·메타데이터 확인 권한도 유지한다. 임시 자격 증명이 먼저 만료되면 URL도 설정한 유효기간보다 일찍 만료될 수 있다. URL 서명 자체는 객체에 HEAD/GET 요청을 보내지 않으며 파일 존재나 실제 IAM 권한을 보증하지 않는다. 자격 증명 공급자가 역할 자격 증명을 가져오거나 갱신하는 과정에서는 네트워크 요청이 발생할 수 있다.

상품 업로드의 `APP_S3_UPLOAD_URL_TTL`과 프로필 업로드의 `APP_PROFILE_IMAGE_UPLOAD_URL_TTL`은 그대로다. `.env.example`은 참고용이며 프로젝트가 `.env`를 자동으로 읽지는 않는다.

## 앱 연동

1. API가 반환한 전체 URL을 변경하지 않고 GET한다. 쿼리 문자열을 제거하거나 별도 인코딩하지 않는다. 백엔드 JWT나 업로드용 헤더를 붙이지 않는다.
2. 업로드 발급 응답의 `expiresIn`·`expiresAt`은 PUT URL의 만료 정보다. GET URL의 유효기간과 다르며 두 URL 모두 발급 시점부터 시간이 흐른다.
3. 만료된 조회 URL은 상품 상세·내 정보·채팅방 상세·주문 상세 등 원래 API를 다시 호출해 갱신한다. 새 URL로 한 번 재시도해도 403이면 반복 갱신하지 말고 서버 권한·객체 존재를 점검한다.
4. URL은 임시 접근 권한이므로 영구 이미지 식별자로 저장하거나 로그에 남기지 않는다. 앱의 이미지 캐시 식별자는 객체 키를 사용하고 네트워크 요청에는 최신 서명 URL을 사용한다.

웹에서 이미지를 fetch한다면 필요한 GET CORS도 별도로 구성한다. S3 공개 접근 차단과 버킷 비공개 정책은 유지한다.

## 검증 범위

로컬 테스트는 테스트용 자격 증명으로 실제 AWS SDK 서명을 생성하고 GET 기준으로 서명을 재계산한다. 객체 경로·인코딩·유효기간·임시 세션 토큰과 실제 상품·프로필·채팅방·주문 HTTP 응답을 검증한다. 최신 develop 통합 후에는 검색·판매자별 목록·관심 상품·팔로우 목록·탈퇴 후 보존된 주문 이미지 응답과 기존 쿼리 수 제한도 함께 검증한다. S3 네트워크 호출은 테스트 대역으로 대체한다.

2026-11-03 최신 develop 기준 `./gradlew test build --console=plain`이 성공했다. JUnit XML 집계는 1,021개 중 750개 통과, 271개 건너뜀, 실패·오류 0개다. PostgreSQL 전용·마이그레이션 테스트는 DB 환경 변수가 없어 건너뛰었다. 이번 변경에는 DB 스키마 변경이 없다. 저장소의 CI 워크플로는 별도 PR에 있어 이번 로컬 검증을 CI 성공으로 간주하지 않는다.

2026-11-03 시드니 개발 EC2에서 수정된 실제 상품·프로필 저장소 클래스로 S3 다운로드를 검증했다. 서비스와 같은 컨테이너 네트워크에서 독립 Java 프로세스를 실행했으며, 장기 키 없이 서버 IAM 역할의 임시 자격 증명과 비공개 개발 버킷을 사용했다.

- 상품·프로필 각각 GET 서명 URL로 HTTP 200, `image/png`, 업로드한 파일과 바이트 일치를 확인했다.
- 기본 만료 시간 900초와 임시 세션 토큰 포함을 확인했다.
- 두 종류 모두 서명 없는 URL 및 변조한 서명은 HTTP 403이었다.
- 2초 유효기간으로 발급한 URL은 만료 후 HTTP 403, 재발급한 URL은 HTTP 200이었다.
- 상품 HEAD 존재 확인과 프로필 메타데이터 조회가 성공했다.
- 검증용 객체와 버전·삭제 마커, 독립 검증 컨테이너·서버 임시 파일을 제거했다. 테스트용으로 추가한 현재 IP의 SSH 규칙도 제거하고 기존 규칙을 유지했다.

이 검증은 서비스 배포와 구분한다. 당시 실행 중인 서비스 JAR는 `f245d92292690fab0db45bc65e198852e824b8ba` 버전으로, GET 서명 수정이 반영되지 않았다. 실제 사용자 로그인 후 API 응답을 통한 이미지 표시는 수정 버전 배포 후 별도 검증해야 한다. 서비스 재시작이나 DB 변경은 하지 않았다.

같은 버킷에서는 기존 키를 그대로 서명하면 되지만, 버킷을 바꾸는 경우 기존 객체를 동일 키로 이관해야 한다. GET 서명이나 IAM 권한 추가만으로 없는 파일을 복구할 수는 없다. 배포와 이미지 이관은 별도 작업이다.
