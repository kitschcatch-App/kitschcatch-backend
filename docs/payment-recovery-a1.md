# PG 승인 직후 프로세스 종료와 자동 복구

추적 이슈는 [#126](https://github.com/kitschcatch-App/kitschcatch-backend/issues/126)이다. 실험 기준은 `1c6ba551249fd66320361a4b29363b9154690f87`이다.

A1 실행기는 주문 생성과 승인에 실제 앱 HTTP API를 사용한다. 별도 JVM이 PG 대역에 승인 POST를 보내면 대역은 요청과 승인 효과를 기록하고 응답을 보류한다. 실행기는 DB에 커밋된 `PROCESSING / PENDING / RESERVED / PROCESSING`을 확인한 뒤 해당 JVM에만 `SIGKILL`을 보낸다. 같은 JAR와 스키마로 다시 시작한 JVM의 스케줄러가 PG 조회로 상태를 확정할 때까지 기다린다.

최종 상태는 `SUCCESS / PAID / SOLD_OUT / SUCCEEDED`다. 최초 예약 소유 주문과 현재 승인 시도가 유지되어야 하며, 같은 승인 요청을 다시 보내도 PG 승인 POST와 승인 효과는 각각 1회, 구매자와 판매자의 성공 알림은 각각 1건이어야 한다.

## 실행

Java 21, Python 3.11 이상, `psql`이 필요하다. 예시는 `127.0.0.1:55486`에 띄운 실험 전용 PostgreSQL에서 전용 DB `kitschcatch_a1`과 로컬 접속 사용자 `a1`을 사용한다. 실행기는 매 회차 새 스키마를 만들고 종료 시 해당 스키마를 삭제한다.

```sh
./gradlew bootJar
python3 scripts/payment_recovery_a1.py \
  --jar build/libs/kitschcatch-backend-0.0.1-SNAPSHOT.jar \
  --db-port 55486 --db-user a1 --db-name kitschcatch_a1 \
  --repeat 3 --out /tmp/kitschcatch-a1-run
```

기본 실행은 복구 스케줄러의 30초 주기와 10초 PG 읽기 제한을 사용한다. `--scan-seconds 1`을 지정하면 재기동 JVM의 스캔 주기를 줄여 실험 장치를 점검할 수 있다. 이 경우의 소요 시간은 기본 설정 결과와 따로 집계한다. 앱은 첫 실행 때 빈 스키마를 생성하고 실행기는 029 SQL의 부분 유일 인덱스 3개를 적용한다. 재기동에서는 스키마 검증 모드를 사용한다.

`manifest.json`에는 체크아웃·JAR 해시와 실행 설정을, `scenario-results.csv`에는 회차별 판정과 시간을 남긴다. 회차 디렉터리에는 두 JVM의 로그, 스키마의 인덱스·제약, PG 요청과 DB 상태 관측을 한 단조 시계로 기록한 `events.jsonl`이 있다. DB 확인은 0.25초 간격으로 폴링하므로 반영 시각에는 폴링 오차가 포함된다.

## 2026-11-12 결과

Java 21.0.7과 PostgreSQL 14.18에서 기준 커밋의 관련 회귀 테스트 51개가 모두 통과했다. 건너뛴 테스트는 0개였다. 재기동 스캔 주기 1초로 장치를 점검한 3회가 모두 통과했다.

기본 30초 주기에서는 같은 호스트와 PostgreSQL 인스턴스에서 서로 다른 스키마를 쓰는 4개 묶음을 병행했다. 각 묶음에서 5회씩 실행해 20회 모두 통과했다. 전 회차에서 강제 종료 뒤 결제는 미확정 상태로 남았고, 재기동한 스케줄러가 조회 1회로 최종 상태를 확정했다. 동일 승인 요청 재전송 뒤에도 승인 POST·승인 효과·승인 시도는 각각 1회, 성공 알림은 구매자와 판매자 각각 1건이었다.

| 기본 주기 20회에서 관측한 구간 | 중앙값 | 최댓값 |
| --- | ---: | ---: |
| PG 대역의 승인 효과 기록부터 SIGKILL 전송까지 | 0.045초 | 0.101초 |
| PG 대역의 승인 효과 기록부터 내부 상태 반영 관측까지 | 42.140초 | 44.415초 |
| 재기동 준비 완료부터 내부 상태 반영 관측까지 | 30.567초 | 31.308초 |

측정값은 로컬 PG 대역과 이 호스트의 실행 조건에 해당한다. 원자료는 작업 공간의 `build/payment-recovery-a1/2026-11-12/`에 있다. 실험 설정, 통합 결과 CSV, 회차별 이벤트와 JVM 로그, 회귀 테스트 XML을 보존했다.
