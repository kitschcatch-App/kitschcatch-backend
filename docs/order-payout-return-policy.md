# 정산과 반품 운영 정책

2026-10-01. 사용자가 정책 결정을 위임하여 아래 내용을 이번 구현의 기본 정책으로 확정했다.

## 지급 업체와 수취 정보

- 토스페이먼츠 지급대행 v2를 사용한다. 운영자가 토스 상점관리자에서 판매자의 실명·연락처·본인 명의 계좌를 등록하고 본인확인과 KYC를 완료한다.
- 백엔드는 계좌번호·예금주·연락처 원문을 저장하지 않는다. 판매자 회원 ID와 토스 Seller ID만 연결한다. 연결 API는 운영자 전용이며 토스 조회 결과의 `refSellerId`와 `APPROVED` 상태를 검증한다.
- `refSellerId`는 `KC` + 회원 ID의 대문자 36진수(최소 5자리, 앞쪽 0 채움)이다. 토스 등록 시 반드시 이 값을 입력한다. 연결 후 Seller ID는 바꾸지 않고 계좌 변경은 토스에서 본인확인 후 처리한다.
- 정산 최초 실행 시 수취 Seller ID와 금액을 주문에 고정한다. 지급 직전에도 토스 셀러의 소유 관계와 승인 상태를 다시 확인한다.
- 지급은 운영자가 영업일 08:00~15:00에 `EXPRESS`로 실행한다. 토스가 영업일·잔액·계좌 상태를 최종 판정한다. 서버는 승인 없이 자동 지급을 예약하지 않는다.
- 요청 ID와 멱등키는 정산 ID로 고정한다. 송금 POST 전의 시간·수취인·잔액 검사 실패는 WAITING으로 돌아가 같은 ID와 저장된 금액으로 재검사한다. 응답 유실 시 같은 지급을 조회하며 새 ID로 송금하지 않는다. 목록 조회 한도를 넘거나 지급 기록을 찾지 못하면 UNKNOWN으로 두고 운영자가 토스 원장을 확인한다.
- 지급 완료는 토스의 COMPLETED와 요청 ID·수취인·금액·통화를 모두 대조한 뒤 기록한다. `settledAt`은 은행 입금 시각이 아닌 서버의 완료 확인 시각이다.

## 수수료

- 플랫폼 수수료 기본값은 거래금액의 5%(500 basis points)이며 원 미만은 버린다. 판매자 지급액은 거래금액에서 수수료를 뺀 금액이다. 12,000원 거래의 수수료는 600원, 지급액은 11,400원이다.
- 최초 정산 실행 시 금액을 고정하므로 이후 설정 변경으로 기존 지급액이 바뀌지 않는다.
- 토스 PG·지급대행 비용은 플랫폼이 부담하며 판매자에게 별도로 차감하지 않는다. 세금계산서·세무 처리와 이미 완료된 지급의 회수는 이 API의 기능이 아니다.

## 반품 승인·거절·철회

- 배송 전 전액 환불은 기존 PG 취소로 처리한다. 배송 후에는 REQUESTED로 접수하고 자동 환불하지 않는다.
- 운영자만 반품을 승인·거절한다. 승인 요청에는 현재 환불 ID, 반품 실물 수령 확인(`returnReceived=true`), 검수·증빙 확인 사유가 필요하다. 상품 하자·오배송·설명 불일치 또는 판매자와 합의한 단순변심을 승인 대상으로 한다.
- 반품 물품은 판매자와 협의한 판매자 수취 주소로 보낸다. 실제 주소는 거래 당사자가 연락 채널에서 전달하며 공통 가상 주소를 만들거나 공개 API에 노출하지 않는다.
- 하자·오배송·설명 불일치의 반품 운임은 판매자, 합의한 단순변심의 운임은 구매자가 부담한다. 운임은 별도 정산하며 PG 환불액에서 임의로 공제하지 않는다.
- 운영자는 증빙 부족·합의되지 않은 단순변심·반품 물품 불일치 등을 사유로 거절할 수 있다. 거절 사유를 반드시 남긴다.
- 구매자는 REQUESTED 상태에서만 철회할 수 있다. 실제 반품 발송 후에는 철회하지 않는 운영 정책이며, 운영자는 실물 수령·귀속을 확인한 뒤 승인한다. PROCESSING/COMPLETED 이후 철회·거절·구매 확정은 차단한다.
- 한 주문의 환불 신청은 한 건으로 유지한다. REJECTED/WITHDRAWN 이후 같은 요청은 기존 결과를 반환하며 새 자동 신청은 만들지 않는다. 이의 제기는 고객지원에서 검토한다. 구매 확정은 다시 가능하다.
- 승인·거절·철회는 현재 환불 ID로 대조하고 주문 잠금으로 직렬화한다. 승인·거절 사유, 처리자와 처리 시각, 철회 시각을 보존한다. 승인 재전송은 PG 취소를 중복 호출하지 않는다.
- 구매 확정 이후 신규 환불을 자동 처리하지 않는다. 이미 지급된 금액이 관련된 분쟁은 고객지원에서 별도로 처리한다.

## 적용과 검증 구분

정책과 코드 구현은 이 작업에서 완료한다. 실제 토스 지급대행 계약, 키 발급, 판매자 등록·KYC, 운영 DB 적용과 실제 송금은 별도 운영 준비다. 테스트 키·로컬 모의 서버의 결과를 실제 입금 검증으로 표시하지 않는다.
