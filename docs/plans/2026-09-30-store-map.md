# 매장 지도 조회 API 구현 계획

- 이슈: [#39](https://github.com/kitschcatch-App/kitschcatch-backend/issues/39).
- 브랜치: `feat/39`, 기준: `develop`의 `6a96902`.
- 사용자는 네이버 지도 SDK를 사용하며, 실제 매장 데이터는 추후 직접 제공한다. 운영자가 검수한 CSV로 관리하되 이번 작업에서 실제 데이터 수집·적재와 적재 도구 구현은 제외한다.

## API 계약

기존 보안 정책을 유지하여 세 API 모두 Bearer access token을 요구한다. 프로필 등록 여부는 제한하지 않는다. 좌표는 WGS84 십진수 위도·경도이며 서버에서 네이버 외부 API를 호출하지 않는다.

| API | 입력 | 응답·정렬 |
| --- | --- | --- |
| `GET /api/stores` | 선택 `region`, `page=0`, `size=20` | `content`, `page`, `size`, `totalElements`, `totalPages`. ID 오름차순. |
| `GET /api/stores/nearby` | 필수 `latitude`, `longitude`, `radiusKm=1`, `page=0`, `size=20` | `stores`, `page`, `size`, `hasNext`. 실제 거리, ID 오름차순. |
| `GET /api/stores/{storeId}` | 양의 정수 ID | 좌표·주소·연락처와 요일별 `businessHours`. |

- Notion 원문: 목록은 `region`과 페이지 응답 및 `phone`, 주변은 `stores`와 `distanceMeters`, 상세는 `phone` 및 요일별 영업시간을 사용한다. 주변 조회에는 과도한 응답을 막기 위해 페이지 정보와 `hasNext`를 추가한다.
- `region`은 서울·부산·대구·인천·광주·대전·울산·세종·경기·강원·충북·충남·전북·전남·경북·경남·제주의 17개 표준 약칭이다. 생략하면 전국, 공백·알 수 없는 값은 거부한다.
- `page`는 0~10000, `size`는 1~100이다. 형식·범위·지역 오류는 400 `COMMON_001`.
- 위도 -90~90, 경도 -180~180, NaN/Infinity 금지. 반경은 1·3·5km만 허용한다. 좌표 누락·형식·범위·반경 오류는 400 `STORE_002`.
- 없는 양의 매장 ID는 404 `STORE_001`; ID 형식·범위 오류는 400 `COMMON_002`.
- 빈 데이터는 200과 빈 배열. 영업시간 미등록은 빈 배열이며 휴무와 구분한다. 휴무일은 `closed=true`, 두 시간은 null. 자정 이후 종료는 `closeTime <= openTime`으로 표현한다.

## 저장·조회 구조

- `stores`: ID, 이름, 표준 지역, 주소, 위도·경도, 선택 전화번호.
- `store_business_hours`: 매장 ID+요일 복합 키, 시작·종료 시각, 휴무 여부. 매장 삭제 시 연결 시간도 제거한다.
- JPA로 목록과 상세를 조회하고 상세의 영업시간은 월요일부터 정렬한다. 목록에서 영업시간을 로드하지 않는다.
- 주변 검색은 DB에서 Haversine 구면 거리를 계산한다. 평균 지구 반지름 6,371,008.8m, 위도 범위와 인덱스로 후보를 줄인 뒤 실제 반경을 적용한다. 경도 경계와 극지에서도 누락되지 않도록 경도 범위 제한을 생략한다.
- 계산 거리를 기준으로 필터·정렬하고 응답에서만 정수 미터로 반올림한다. 반경 포함 비교에는 부동소수점 오차 0.000001m만 허용한다. 같은 좌표의 서로 다른 매장을 합치지 않는다.
- DB에서 `size+1`개만 읽고 다음 페이지 존재 여부를 반환한다. 운영 규모가 커지면 실측 후 PostGIS 또는 공간 인덱스 도입을 별도 검토한다.
- 재실행 가능한 수동 SQL `039_stores.sql`로 테이블·FK·좌표/시간 제약·인덱스를 제공한다. Hibernate 자동 생성은 수동 SQL 검증의 대체물이 아니다.

7. 격리 PostgreSQL에서 수동 SQL 재실행·제약·검색 결과 검증.

테스트 fixture는 가상의 데이터만 사용한다. 운영 DB 적용, 실제 데이터 적재, 앱의 네이버 SDK 화면/키 검증은 완료로 표기하지 않는다. 템플릿에 맞춘 Open PR을 develop 대상으로 생성한다.
