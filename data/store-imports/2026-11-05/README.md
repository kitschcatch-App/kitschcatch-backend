# 첫 개발 매장 배치

이슈 [#81](https://github.com/kitschcatch-App/kitschcatch-backend/issues/81)의 개발 DB 등록 자료다. 가챠·피규어·캐릭터 굿즈를 판매하는 오프라인 매장 30곳을 골랐다. 서울 18곳, 경기 6곳, 부산 4곳, 대전 1곳, 제주 1곳이다.

- [stores.csv](stores.csv)는 고정 내부 ID와 매장 기본 정보 30행이다. 8번은 안국점 검수 보류로 비워 두었다. 이미 등록된 ID는 재수집하거나 정렬해도 바꾸지 않는다.
- [business-hours.csv](business-hours.csv)는 28개 매장의 확인된 정규 요일 시간 194행이다. 출처가 확인된 매장 문의 번호는 23곳에 기입했다. 휴일 예외나 격주 휴무를 현재 형식으로 표시할 수 없어, 격주 휴무에 해당하는 요일은 생략했다.
- [sources.csv](sources.csv)는 매장별 공식 안내와 보조 출처, 좌표를 대조한 공공데이터 원본 행 ID, 기준일 및 확인일이다. `coordinate_kind=store`인 5곳은 동일 매장의 원본 행에 매칭했다. 나머지 25곳은 동일 도로명주소의 건물 좌표다. `coordinate_source_row_id`는 이 경우 좌표 근거 행을 가리키며, 해당 매장의 외부 ID를 뜻하지 않는다. 건물의 층과 호수는 상세 주소에서 확인한다.

좌표는 [소상공인시장진흥공단 상가·상권 정보](https://www.data.go.kr/data/15083033/fileData.do)의 2026-09-30 기준 배포본을 사용했다. 공공데이터포털에서 이용허락범위 제한 없음으로 안내한다. 원본 ZIP의 SHA-256은 `c83b30e7a1d1144864a91d0e1818abf360f565972878d6e3c88d75ceafe2286a`다. 매장명·상세 주소·연락처·시간은 매장 운영사나 입점 시설의 안내에 있는 사실을 정리했다.

| 보류 또는 제외 | 사유 |
| --- | --- |
| 팝마트 안국점 | 공식 매장 목록에서 확인했으나 이번 공공데이터 기준일의 동일 주소 좌표를 확인하지 못했다. |
| 애니플러스샵 대전 중앙로점·광주 충장로점 | 예전 지점 페이지와 현재 공식 매장 목록이 다르다. 현재 목록에서 빠진 두 지점은 보류했다. |
| 애니메이트 부산점 이전 주소 | 공식 지점의 현재 주소가 가야대로 772로 변경되어, 중앙대로 672에 남아 있는 공공데이터 매장 행은 사용하지 않았다. |
| 피규어프레소 에프레소점 이전 주소 | 공식 이전 공지의 신도림 테크노마트 주소를 적용했다. 홍대 에프피점은 같은 공지에서 계속 운영을 확인했다. |

## 적용 기록

[기존 CSV 도구 절차](../../../docs/issue-55-store-csv.md)에 따라 격리 PostgreSQL에서 `dry-run`과 실제 적용을 진행했다. 같은 파일을 재적용했을 때 매장 30행·영업시간 194행과 기존 관심 관계가 유지됐고, 다음 자동 ID가 가장 큰 매장 ID보다 큰 것을 확인했다. 별도 실행한 CSV 파서·PostgreSQL 테스트 35개가 모두 통과했다.

2026-11-05 14:38 KST에 시드니 개발 환경의 `public` 스키마에 적용했다. 적용 직전 매장·영업시간은 각 0행이었다. 적용 후 읽기 전용 조회에서 매장 30행, 영업시간 194행, 이름과 주소가 같은 중복 매장 0그룹을 확인했다.

| 기록 | 값 |
| --- | --- |
| 적용 이력 ID | `9e867d02-e3fc-4f13-9aae-251b2853a678` |
| 매장 CSV SHA-256 | `22435a189ab88651bac2369e69b8b79305fd90e3dd3042dcb9617e49cc0d9249` |
| 영업시간 CSV SHA-256 | `a3c9eda1c0917523113223508600adebf1ea995ba399d17ebdd1b7ad01b8dc58` |

동일 배치를 재검사할 때는 검수한 파일의 해시와 대상 환경을 대조한 뒤 `storeCsv`의 `dry-run`으로 기존 행 30건인지 확인한다. 변경할 매장만 제출할 경우 기존 내부 ID를 사용하고, 확인된 전화번호와 영업시간을 검수한다. 기존 CLI는 빈 전화번호를 NULL로 적용하며, 빠진 매장과 요일은 그대로 둔다.

개발 서버 HTTPS API에서 목록 2페이지, 5개 지역 필터, 매장 상세 30건의 기본 정보·전화·영업시간을 CSV와 대조했다. 합정·홍대·제주의 3 km 주변 검색 결과와 거리 정렬을 확인했다. 임시 계정으로 관심 등록·목록·해제를 검증한 후 계정을 제거했다.
